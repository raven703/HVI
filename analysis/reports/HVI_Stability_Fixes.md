# Runtime stability revision

* Exact-length overlapped byte-stream transfers now accumulate partial reads/writes under one deadline. Timeouts and IO errors counted. Stop event interrupts Runtime waits. Cancellation waits only 200 ms; pathological incomplete operations retain private OVERLAPPED/buffer/event memory until signalled, avoiding caller-stack use-after-free. Pending-cancellation count is exposed. This is bounded user-mode waiting, not a hard OS/driver completion guarantee. Pathological retained operations can persist to process exit; normal test runs require zero pending cancellations. No unbounded GetOverlappedResult(TRUE) remains in new transport.
* Pipe created synchronously before Initialize succeeds. Duplicate session ownership fails immediately. Same handle is reused for reconnect. Shutdown signals stop, joins thread, closes resources and resets state. Repeated lifecycle tested.
* Pipe DACL restricts to current user; remote clients rejected. Before first command is applied, impersonated client token must match user SID, authentication/logon LUID and Windows session. PID exposed. This is NOT a signed-binary allowlist: another same-user/same-logon program can control the test runtime. Restrict use to trusted local desktop. Different-user/session rejection path requires multi-account testing and remains not experimentally exercised.
* Invalid protocol/session/sequence/parameters rejected before ACK. Invalid async indices/null/structure sizes checked. Mutex lock order is device then feed; generation synchronization and mouse snapshots are atomic under feed lock.
* EventBuffer records exact last evicted order; keyboard gaps no longer look like mouse loss, and genuine upstream loss reports DI_BUFFEROVERFLOW. Bounded queues cannot retain unlimited events: overflow is explicit, not concealed or described as lossless. Device readers remain isolated.
* Mouse reset epoch avoids phantom inverse deltas after Reset/ResetMouse; keyboard state unaffected by ResetMouse. Atomic COM counts expose outstanding objects. DLL must not be unloaded with live objects/worker; no unsafe auto-shutdown in DllMain.
* Controller has dedicated IO worker, per-session ACK sequences, heartbeat/reconnect, bounded command queue with explicit safety reset/counter on saturation. Legacy console/probe server paths remain historical and synchronous; this revision does not claim repository-wide transport replacement.

Tests: stability_tests checks real DLL identity diagnostics, stalled-peer timeout/reset, reconnect, invalid protocol, bounded idle shutdown, repeated init/shutdown, zero live COM/pending IO; tests also cover mouse overflow/gaps/reset and concurrent feed reset/read. GUI integration checks independent live API observations and owned-process exit. These are scoped resource checks, not a general heap leak profiler or formal race proof.
